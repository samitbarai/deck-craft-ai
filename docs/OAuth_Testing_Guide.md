# OAuth Testing Guide for DeckCraft AI

This guide explains how to properly test the Google OAuth integration endpoints, including the callback endpoint which requires special handling.

## 🚀 Quick Test Sequence

### 1. Start OAuth Flow
```bash
curl http://localhost:8000/api/v1/auth/google/login
```

**Expected Response:**
```json
{
  "success": true,
  "authUrl": "https://accounts.google.com/o/oauth2/v2/auth?access_type=offline&scope=...",
  "message": "Redirect user to this URL to authorize Google Slides access"
}
```

### 2. Complete OAuth in Browser
1. Copy the `authUrl` from step 1
2. Open in browser
3. Sign in with your Google account (`samit403@gmail.com`)
4. Grant permissions

**Expected Result:** Browser redirects to callback URL and shows:
```json
{
  "success": true,
  "message": "Google authentication successful",
  "user_id": "90b2d2a2-83e2-4b10-be5d-0721bb20279b",
  "scopes": ["https://www.googleapis.com/auth/userinfo.profile", "openid", ...]
}
```

### 3. Verify Authentication Status
```bash
curl http://localhost:8000/api/v1/auth/google/status
```

**Expected Response:**
```json
{
  "success": true,
  "authenticated": true,
  "user": {
    "id": "90b2d2a2-83e2-4b10-be5d-0721bb20279b",
    "email": "samit403@gmail.com",
    "name": "Your Name",
    "picture": "https://..."
  },
  "providers": ["google"],
  "message": "User is authenticated with Google"
}
```

### 4. Test Google Slides API Access
```bash
curl http://localhost:8000/api/v1/auth/google/test
```

**Expected Response:**
```json
{
  "success": true,
  "message": "Google Slides API access working",
  "templatesFound": 2,
  "templates": [
    {
      "id": "1ABC123...",
      "name": "Template 1",
      "mimeType": "application/vnd.google-apps.presentation"
    }
  ]
}
```

## 🔍 Testing the OAuth Callback Endpoint

### ⚠️ **Important: Why Direct Testing Doesn't Work**

The callback endpoint **cannot be tested directly** in Postman with fake values because:

1. **State Parameter Security:** Must be generated by our server and stored temporarily
2. **Authorization Code:** Must be a real code from Google (expires in 10 minutes)
3. **CSRF Protection:** State validation prevents unauthorized access

### ✅ **Proper Testing Methods**

#### Method 1: Complete OAuth Flow (Primary)
This is the **only way** to fully test the callback:

1. **Monitor Server Logs:**
   ```bash
   # Watch terminal running: npm run dev
   # Look for these log entries (actual format):
   [UTC_TIME] INFO: incoming request
       reqId: "req-X"
       req: {
         "method": "GET",
         "url": "/api/v1/auth/google/callback?state=...&code=...",
         "host": "localhost:8000",
         "remoteAddress": "127.0.0.1",
         "remotePort": XXXXX
       }
   [UTC_TIME] INFO: Google OAuth successful for user: 90b2d2a2-83e2-4b10-be5d-0721bb20279b
       reqId: "req-X"
   [UTC_TIME] INFO: request completed
       reqId: "req-X"
       res: {
         "statusCode": 200
       }
       responseTime: XXX.XX
   ```

2. **Complete Full Flow:** Follow steps 1-2 above and watch the callback execute automatically

#### Method 2: Browser Developer Tools
1. Open browser → F12 → Network tab
2. Complete OAuth flow (steps 1-2 above)
3. See callback request/response in Network tab

#### Method 3: Invalid State Testing (For Error Handling)
Test error handling with the Postman endpoint:
```
GET /api/v1/auth/google/callback?state=INVALID_STATE&code=INVALID_CODE
```

**Expected Response (400 Bad Request):**
```json
{
  "success": false,
  "error": "Invalid or expired OAuth state"
}
```

## 🧪 **Postman Collection Usage**

### OAuth Flow Testing in Postman

1. **"Start OAuth Flow"** - Get authorization URL
2. **Manual Browser Step** - Complete OAuth in browser (cannot be automated)
3. **"Check Authentication Status"** - Verify OAuth worked
4. **"Test Google Slides API Access"** - Test actual API connectivity
5. **"Refresh Access Token"** - Test token refresh
6. **"Disconnect Authentication"** - Test cleanup

### Callback Endpoint in Postman
The **"OAuth Callback (Manual Test)"** endpoint in Postman:
- **Purpose:** Documentation and error testing only
- **Expected Behavior:** Always returns 400 error with fake values
- **Real Testing:** Use complete OAuth flow in browser

## 🔐 **Security Features Tested**

### State Parameter Protection
```bash
# This will fail (expected behavior):
curl "http://localhost:8000/api/v1/auth/google/callback?state=fake&code=fake"
# Response: {"success": false, "error": "Invalid or expired OAuth state"}
```

### Authorization Code Validation
```bash
# This will fail with valid state but invalid code:
curl "http://localhost:8000/api/v1/auth/google/callback?state=VALID_STATE&code=invalid"
# Response: {"success": false, "error": "Failed to complete Google authentication"}
```

### Token Encryption
Tokens are automatically encrypted before database storage using AES-256-CBC.

## 🚨 **Troubleshooting**

### Common Issues

#### 1. "Invalid or expired OAuth state"
- **Cause:** Using fake/old state parameter
- **Solution:** Generate fresh state with `/login` endpoint

#### 2. "No access token received from Google"
- **Cause:** Invalid authorization code or expired code
- **Solution:** Complete fresh OAuth flow

#### 3. "invalid input syntax for type uuid"
- **Cause:** Database expects UUID but received string
- **Solution:** Check user_id format (should be UUID)

#### 4. "User not authenticated with Google"
- **Cause:** No valid tokens in database
- **Solution:** Complete OAuth flow first

### Debug Mode
Add detailed logging by checking server logs during OAuth flow:
```bash
# Server logs show:

[INFO] incoming request: GET /api/v1/auth/google/callback?state=...&code=...
[INFO] Google OAuth successful for user: [UUID]
```

4. ✅ Tokens stored in database (encrypted)

## 🎯 **Best Practices**

1. **Always test complete OAuth flow** - Don't rely on manual callback testing
2. **Monitor server logs** during testing for debugging
3. **Use browser developer tools** to inspect OAuth redirects
4. **Test error scenarios** with invalid states/codes
5. **Verify token encryption** in database
6. **Test token refresh** before expiration
7. **Test cleanup** with disconnect endpoint

## 📝 **Notes**

- OAuth state parameters expire after 10 minutes
- Authorization codes from Google expire quickly
- Refresh tokens allow long-term access without re-authentication
- All tokens are encrypted before database storage
- CSRF protection prevents unauthorized callback access

---

**Remember:** The callback endpoint is designed to be called by Google, not manually by developers. Use the complete OAuth flow for proper testing.
